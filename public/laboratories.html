ПИРИП · Пять лабораторных работ

Сохранённые задания исходного курса. Это учебная практика. Схема из четырёх таблиц, PHP/MySQL и правило одного отзыва — решения курса. В подготовительный день ДЭ код не пишут и БД не проектируют.

  • У каждой функции есть источник и проверка
  • ER-диаграмма совпадает со schema.sql

  • README не содержит вымышленных требований

  • Выполнить seed.sql → Появляются три типа помещений и администратор

  • Пароль администратора записан открытым текстом

Восстановление

  • Если связь неясна — сформулируйте, кому принадлежит заявка и к чему относится отзыв
  • Если требований слишком много — вернитесь к страницам 33–37 КИМ

2. Рабочее приложение — задание 1

Реализовать полный сценарий регистрации, заявки, администрирования и отзыва на PHP + MySQL с серверной защитой.

Учебная рекомендация: 180 минут.

  • Шаблон PDO-подключения
  • Базовые классы User, Auth, Reservation и Review

1. Подключите БД и модели

  • Проверьте PDO на SELECT 1
  • Реализуйте методы доступа к users и venues
  • Заполните справочник помещений

Результат: Приложение читает данные из подготовленной БД.

  • src/Database.php
  • src/User.php
  • src/Venue.php

2. Реализуйте регистрацию и вход

  • Проверьте все обязательные поля на сервере
  • Проверьте уникальность логина
  • Сохраните password_hash
  • Создайте и завершайте сессию

Результат: Корректный пользователь входит; неверные данные дают понятную ошибку.

  • public/register.php
  • public/login.php
  • public/logout.php
  • src/Auth.php

3. Добавьте заявку и кабинет

  • Загрузите select помещений из БД
  • Проверьте дату и способ оплаты
  • Создайте status=new
  • Покажите только заявки текущего пользователя

Результат: Новая заявка сохраняется и появляется после обновления кабинета.

  • public/reservation-create.php
  • public/account.php
  • src/Reservation.php

4. Защитите администратора

  • Проверьте role=admin до вывода
  • Покажите все заявки
  • Разрешите только три статуса
  • Сохраните смену статуса подготовленным запросом

Результат: Conf2027 / Demo77 управляет заявками; пользователь получает 403.

  • public/admin.php
  • src/Auth.php
  • src/Reservation.php

5. Добавьте отзыв и проверку

  • Покажите форму только для completed
  • Повторите проверку на сервере
  • Запретите второй отзыв
  • Выполните коммит lab2-ready

Результат: Отзыв существует только у завершённой заявки владельца.

  • README.md

Что сдаём

  • Рабочая БД и ER
  • Регистрация и авторизация
  • Кабинет и заявка
  • Панель администратора
  • Отзыв
  • Коммиты start-task1 и lab2-ready

Учебная приёмка

  • Использован полный стек и ООП
  • Пароли хешируются
  • SQL параметризован
  • Пользователь не видит чужие заявки
  • Роль проверяется на сервере
  • Отзыв доступен только после завершения

Проверки

  • Зарегистрироваться с коротким паролем → Пользователь не создаётся; ошибка показана на форме
  • Открыть admin.php под ролью user → HTTP 403 или безопасный редирект
  • Создать заявку и обновить страницу → Заявка остаётся со статусом «Новая»
  • Добавить отзыв до завершения → Сервер отклоняет операцию

Типичные ошибки

  • Проверка роли есть только в меню
  • user_id принимается из query
  • Пароль сравнивается как обычная строка
  • UPDATE статуса принимает произвольное значение

Восстановление

  • Ошибка БД: проверьте сервис, параметры, схему и SELECT 1
  • Ошибка входа: проверьте найденного пользователя, password_verify и session_start
  • Чужие записи: добавьте WHERE user_id = id из сессии

Передача результата

  • Ссылка на репозиторий
  • Хеш lab2-ready
  • Показ регистрации, заявки, статуса и отзыва за 4 минуты
